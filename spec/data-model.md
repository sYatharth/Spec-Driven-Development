- **Stage:** Specification (step 2)

## 1. Entity–Relationship Overview

```
┌──────────────────────────┐          1      *   ┌──────────────────────────┐
│         TICKET           │────────────────────▶│        COMMENT           │
├──────────────────────────┤   ticket_id (FK)    ├──────────────────────────┤
│ id          BIGINT  PK   │                     │ id         BIGINT  PK     │
│ title       VARCHAR(150) │                     │ ticket_id  BIGINT  FK     │
│ description VARCHAR(5000) │                    │ author     VARCHAR(100)   │
│ status      VARCHAR(20)  │                     │ body       VARCHAR(2000)  │
│ priority    VARCHAR(20)  │                     │ created_at TIMESTAMP      │
│ assignee    VARCHAR(100) │                     └──────────────────────────┘
│ created_at  TIMESTAMP    │
│ updated_at  TIMESTAMP    │
└──────────────────────────┘
```

One Ticket has many Comments. Deleting a ticket cascades to its comments (though delete is out of scope for the API in v1).

## 2. Enums

### TicketStatus
`OPEN`, `IN_PROGRESS`, `RESOLVED`, `CLOSED`, `CANCELLED`
- Default on create: `OPEN`.
- Stored as `STRING` (readable in DB, stable across ordinal changes).

### Priority
`LOW`, `MEDIUM`, `HIGH`, `URGENT`
- Default on create: `MEDIUM`.
- Stored as `STRING`.

## 3. Ticket

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| id | Long | PK, generated identity | Immutable |
| title | String | **NOT NULL**, 1–150 | FR-4 |
| description | String | **NOT NULL**, 1–5000 | FR-5 |
| status | TicketStatus | **NOT NULL**, default OPEN | FR-11, state machine |
| priority | Priority | **NOT NULL**, default MEDIUM | FR-6 |
| assignee | String | nullable, ≤100 | FR-7 |
| createdAt | Instant | **NOT NULL**, set `@PrePersist` | server-managed |
| updatedAt | Instant | **NOT NULL**, set `@PrePersist`/`@PreUpdate` | server-managed |

**Validation (Bean Validation on DTOs, not entity-only):**
- `title`: `@NotBlank @Size(max=150)`
- `description`: `@NotBlank @Size(max=5000)`
- `priority`: `@NotNull` (enum-bound; invalid value → deserialization/`400`)
- `assignee`: `@Size(max=100)` (nullable)

**Indexes**
- `idx_ticket_status` on `status` (FR-10 filter).
- Search (FR-9) uses `LIKE`/`ILIKE` on title+description; a full-text index is out of scope v1.

## 5. JPA Mapping Notes

- `Ticket.comments`: `@OneToMany(mappedBy="ticket", cascade=ALL, orphanRemoval=true)`, `@OrderBy("createdAt ASC")`.
- `Comment.ticket`: `@ManyToOne(fetch=LAZY)`, `@JoinColumn(name="ticket_id")`.
- Enums: `@Enumerated(EnumType.STRING)`.
- Timestamps via `@PrePersist` / `@PreUpdate` lifecycle callbacks (or `@CreationTimestamp`/`@UpdateTimestamp`).
- Detail responses map comments to `CommentResponse` to avoid lazy-loading serialization issues.

## 6. Schema DDL (H2 / PostgreSQL-compatible, generated by JPA in dev)

```sql
CREATE TABLE ticket (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title       VARCHAR(150)  NOT NULL,
  description VARCHAR(5000) NOT NULL,
  status      VARCHAR(20)   NOT NULL DEFAULT 'OPEN',
  priority    VARCHAR(20)   NOT NULL DEFAULT 'MEDIUM',
  assignee    VARCHAR(100),
  created_at  TIMESTAMP     NOT NULL,
  updated_at  TIMESTAMP     NOT NULL
);
CREATE INDEX idx_ticket_status ON ticket(status);

CREATE TABLE comment (
  id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  ticket_id  BIGINT        NOT NULL REFERENCES ticket(id) ON DELETE CASCADE,
  author     VARCHAR(100),
  body       VARCHAR(2000) NOT NULL,
  created_at TIMESTAMP     NOT NULL
);
CREATE INDEX idx_comment_ticket ON comment(ticket_id);
```

> In dev, `spring.jpa.hibernate.ddl-auto=update` generates this from entities. For production/Postgres, a Flyway migration mirroring the above is recommended (out of scope v1, noted for review).

## 7. Persistence Durability (NFR-1)

H2 in **file mode** (`jdbc:h2:file:./data/tickets`) writes to disk, so tickets and comments survive application restart — validated by the acceptance test "Data survives application restart".
